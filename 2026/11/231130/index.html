宝塔上的 Nginx 升到 1.30.7，修复高危漏洞

发表于 2026-11-23 分类于 运维 阅读次数： Disqus：
本文字数： 2.1k 阅读时长 ≈ 8 分钟
内网机器、宝塔面板、没有外网，业务里还挂着 lua。折腾了一晚上把 Nginx 编到 1.30.7，记一下 lua-resty-core 版本配对、sticky 模块编不过、srclib 相对路径这三个坑。

这台生产环境服务器在内网，出不去。宝塔自带的 Nginx 用了两三年，业务里挂着 lua 重写和缓存清理，面板上那个”升级”按钮点了也白点——它得联网下包，而且一升级就把你之前编进去的第三方模块全丢了。

所以只能自己编：本地把源码下齐，传进去，按老参数重新编一个二进制，最后把文件换掉。

折腾了大半个晚上。三个地方卡住，记下来。

为什么要升这一版

不是想用新功能，是补漏洞。

Nginx 在 1.30.7 和 1.31.9 这两个版本线上同时修了同一批问题，官方公告里写的是 Not vulnerable: 1.31.9+, 1.30.7+。落到这台机器上，真正要命的是这三条：

CVE 问题 级别 影响范围
CVE-2026-123007 HTTP/2 流控内存破坏 严重 1.9.5 – 1.31.8
CVE-2026-118899 TLS 1.3 下读请求体死循环 严重 1.13.0 – 1.31.8
CVE-2026-123633 HTTP/2 释放后使用 中 1.19.7 – 1.31.8

ssl 和 http_v2 都开着，等于摆在公网上。同一批里还有几条，只影响 mail 模块、http_v3、stream 的，这台机器都没编进去，就不管了。

另外宝塔那个二进制本来就落后好几个版本，这次一步跳到 1.30.7，中间那几批补丁也算一起补上了。

升完只认 nginx -v，面板软件商店里的版本号不会跟着变，别被它吓一跳。

换编译参数

改完看一眼，别带着相对路径往下走：

--with-ipv6 得删。1.25 之后这选项没了（IPv6 默认开），留着 configure 会报 invalid option。--with-openssl 和 --with-pcre 指向源码树里自带的那份，这次没 HTTP/3 需求，删掉用系统的 libssl、libpcre 就行。

坑二：sticky 模块跟 1.30.7 编不过

老参数里有 nginx-sticky-module，我把 nginx-goodies-nginx-sticky-module-ng 下下来了，make 阶段炸，报错大意是：

这模块直接改 Nginx 内部的请求头结构体，属于深度侵入，版本一跳就没了。

好在这功能官方早收编了：Nginx 1.29.6 起原生支持 sticky cookie，upstream 会话保持不用再靠第三方模块。我查了下现有配置里压根没用 sticky 指令，参数删掉，业务无感。

顺带一句经验，改 Nginx 内部结构体的模块，跨大版本基本都要重写；像 cache_purge、dav-ext 这种只做 filter 的，活得久得多。

configure 和 make

configure 跑完看三处：四行 adding module in /www/server/nginx/src/...、summary 里用的是 system PCRE/OpenSSL/zlib、nginx path prefix 还是 /www/server/nginx。三样都对，基本就没问题。

make 完的产物在 objs/nginx。

坑三：参数里带引号会被切坏

这条我没撞上，是后来写脚本时才意识到的。

上面那种 $(echo "$OLD" | sed ...) 拼字符串的做法，如果旧参数里有 --with-cc-opt='-O2 -g -pipe' 这种带引号的多词选项，交给 shell 时会按空格切成两个参数，configure 就报参数错误。我这台没有 cc-opt，所以 sed 够用；要是你那台有，别用这种拼法，老老实实按 token 逐个处理。
